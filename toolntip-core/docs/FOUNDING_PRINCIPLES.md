# Toolntip Founding Principles

Version: 1.0

These principles guide every architectural and product decision made for Toolntip.

---

## 1. Users First

Every feature must solve a real user problem.

We do not build features simply because competitors have them.

---

## 2. Quality Over Quantity

100 high-quality tool pages are better than 10,000 low-quality pages.

Every tool should be complete, accurate, and regularly verified.

---

## 3. Reusable Architecture

Every feature should be reusable.

If code is copied twice, it probably belongs in a reusable component.

---

## 4. Single Responsibility

Each helper, class, template, and component should have one clear responsibility.

---

## 5. WordPress Standards

Whenever possible:

- Follow WordPress Coding Standards
- Follow WordPress Architecture
- Use WordPress APIs

Never reinvent WordPress.

---

## 6. Data First

Data should be structured before presentation.

Templates should render data.

Helpers should prepare data.

Business logic should never live inside templates.

---

## 7. Long-Term Thinking

Every feature should support future expansion.

We prefer architecture that scales rather than shortcuts that create technical debt.

---

## 8. Honest Reviews

Toolntip provides objective software information.

Editorial opinions should be transparent and based on real evaluation.

---

## 9. Performance Matters

Fast websites create better user experiences.

Performance is a feature.

---

## 10. Continuous Improvement

Toolntip is never "finished."

Every release should improve the platform while preserving stability.
